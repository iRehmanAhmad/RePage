  - Responsive ribbon organization across 1024px–1920px viewports with ARIA accessibility.
- **Preflight & Print Production Engine (M8 Phase 0)**:
  - Multi-axis preflight diagnostics (image DPI calculation, boundary checks, overset text detection, font license compliance).
  - Target-specific preflight options (`targetDpi: 300`, `pressReady: true`).
- 127 test files (474 test cases) of automated unit and integration tests (`vitest`).
- **Linked text-frame flow (Phase 2)**: text frames can be linked into flow chains from the ribbon (Shape Format → Text Flow → "Link frame…", target picker by page; "Unlink" breaks the chain). Story text is distributed across chained frames at word boundaries (`computeChainTextSlices` in `domain/document/textFlow.ts`) and rendered per-frame on the canvas; sequence badges `[#1]`, `[#2]` and the `[+]` overflow badge reflect the chain. Commands: `linkTextFramesCommand` / `unlinkTextFrameCommand` in `editor/commands/documentCommands.ts`.
  - **Measured shaping (Phase 2 batch 2)**: on-screen slice layout accepts an optional `ChainTextMeasurer`; the canvas adapter (`editor/canvas/canvasTextMeasurer.ts`, offscreen 2D canvas) measures real advance widths with font-load guards, falling back to the deterministic heuristic when fonts aren't loaded or no DOM exists. Headless paths (export, overflow flags, story fork) keep the heuristic.
  - **Story fork on unlink (Phase 2 batch 2)**: unlinking now forks the story — the detached frame's subchain gets an independent story copy with the text it displayed (middle/tail: A→F→G becomes A + F→G; head: A→B→C becomes A + B→C). Paragraphs are split at run level, preserving marks, styleId stamps, and paragraph attributes. Middle-frame unlink no longer splices the chain shut.
- **Urdu spellcheck hardening (Phase 2 batch 3)**: vendored 30,122-word Urdu wordlist (tesseract-ocr/langdata, Apache-2.0 — see `docs/DEPENDENCIES.md`; generated by `scripts/build-urdu-wordlist.mjs` into `src/domain/language/urduWordlist.generated.ts`). Inline wavy-red underlines in both Tiptap editors (ProseMirror decoration plugin, 350 ms debounced, native browser spellcheck disabled to avoid double marks); right-click menu with ranked Damerau-Levenshtein suggestions, Add to dictionary (persisted personal dictionary), Ignore for session; ribbon (Urdu Tools → Proofing) and status-bar toggle persisted in localStorage. Urdu-aware tokenizer skips numbers/URLs/emails/single chars; aerab-insensitive lookup keys (document text never normalized). The Language Tools panel uses the same engine via the unchanged `checkUrduText` API.
- **English spellcheck (Phase 3 batch 5)**: vendored 148,588-word English wordlist (same tesseract-ocr/langdata source, Apache-2.0 — see `docs/DEPENDENCIES.md`; generated by `scripts/build-english-wordlist.mjs` into `src/domain/language/englishWordlist.generated.ts`, with 15 documented known-typo exclusions for misspellings that leaked into the frequency-derived upstream list, plus a 5,000-word frequency head used to rank suggestions). The engine (`urduSpellchecker.ts`) now classifies each token by script: Latin tokens are checked against the English set (case-insensitive; contractions via apostrophe-stripped forms; possessives via stem), Arabic-script tokens keep the exact Urdu behavior, and mixed-script tokens are skipped conservatively. English suggestions use the same banded Damerau-Levenshtein (threshold 2) + length buckets, ranked by distance, then frequency rank, then same-letter transposition — "teh" → "the" ranks first. Session ignore and the personal dictionary apply to English words too. `checkUrduText()` API unchanged; the inline highlighter and context menu pick English support up automatically.
- **Style gallery management (Phase 2 batch 2)**: all style context-menu items are real — Rename (display-name override, styleId association intact), Remove from Style Gallery (reversible in the Styles Manager), Add to Quick Access Toolbar (pins `style:<id>` keys into the real persisted QAT; clickable in the header, manageable in the QAT customize dropdown), Select All Instances (finds `styleId`-stamped paragraphs via `findStyleInstances`, selects the first containing frame). `applyStyleToStory` stamps `paragraph.styleId`; the ribbon gallery renders from the shared `GALLERY_STYLE_IDS` order.

- **DOCX import (Phase 3 batch 1)**: real end-to-end `.docx` import. `src/persistence/import/docxParser.ts` unzips with the already-depended JSZip (hardened: entry-count cap, incremental uncompressed-size cap against ZIP bombs, path-traversal rejection) and parses `word/document.xml` namespace-agnostically: paragraphs, runs (bold/italic/underline/strike/sub/sup/color/highlight/size/fonts), headings (pStyle + outlineLvl → style presets, emphasis baked into runs), lists (numbering.xml with hierarchical markers, bullet fallback + warning when numbering is missing), alignment, bidi/RTL detection, simple tables (gridSpan/vMerge, cell shading), inline images (rels → `word/media`, magic-byte sniffing), footnotes (appendix section), tracked insertions accepted / deletions dropped / comments+OLE+textboxes counted and reported. `importDocxFile` (`src/persistence/import/docxImporter.ts`) assembles through `editor/commands` (`addFullPageTextFrame`, `linkTextFramesCommand`, new `addImportedTable`): text flows across chained full-page frames, tables/images go on dedicated pages after the text with marker paragraphs at anchor positions, footnotes append as a حواشی section. Output is zod-validated (`parseDocument`) before return. File → Import → "Word document (.docx)" in the backstage, plus drag-and-drop/ribbon open; an `ImportReportDialog` shows countable results and honest drop notes. Urdu text is never normalized. Limits: 50 MB file, 50k paragraphs, 100 images (15 MB each), 300-row tables, parse timeout.
- **TXT / RTF / HTML import (Phase 3 batch 4)**: the plain-text, RTF and HTML importers no longer return orphan story results that the app silently dropped — each now has an end-to-end document builder returning a zod-validated `RePageDocument` plus the same `ImportReport` contract as DOCX, so the ImportReportDialog shows for these formats too. Shared assembly lives in `src/persistence/import/storyAssembler.ts` (story → chained full-page frames → dedicated image pages → `parseDocument`). TXT (`importTextFile`): one paragraph per line, interior blank lines kept as empty paragraphs, text preserved byte-for-byte (fatal UTF-8 decode, no normalization). RTF (`importRtfFile`): the parser was rebuilt byte-oriented with a group state stack, destination skipping, font/color table lookups, alignment + `\rtlpar`, `\uN` escapes, and legacy codepage decoding via both `\ansicpg` and per-font `\fcharset` (cp1256 covers Word's Arabic/Urdu files); table structure, embedded pictures, headers/footers, footnotes and OLE objects are counted and reported, never mangled (table cell text survives as paragraphs). HTML (`importHtmlFile`): sanitized first, then a recursive DOM walk (the old `querySelectorAll` walk double-counted nested blocks) supporting headings, lists with literal markers, blockquote, inline marks/styles, tables (structure dropped, cell text kept) and `data:`-URI images as real assets; external images are counted and reported.
- **Asset round-trip hardening (Phase 3 batch 1, related fix)**: `createUrdupPackage` now falls back to decoding an asset's runtime `dataUrl` when no raw bytes are supplied, so imported (and UI-added) images survive saving; `openDocumentWorkflow` re-attaches displayable `dataUrl`s from package bytes on open; `computeSha256Hash` fallback emits schema-shaped 64-hex so validation never fails without WebCrypto.
- **Pakistani template gallery (Phase 3 batch 2)**: `src/templates/` holds six print-ready builder functions — امتحانی پرچہ (exam paper, A4), ورک شیٹ (school worksheet, A4), شادی کارڈ (wedding card, 5×7 in), اخباری کالم (two-column newspaper column, A4), لیٹر ہیڈ (letterhead, A4), نعت کا صفحہ (naat page, A5). Shared helpers (`helpers.ts`) for pages, text frames, rules, borders and ruled answer lines; all content in proper Urdu with bracketed placeholders, RTL-correct, preflight-clean (OFL fonts only). File → New → Templates gallery in the backstage (`FileBackstageOverlay.tsx`) with Urdu/English cards; selection goes through the `file.newFromTemplate` command. 16 tests cover build/validation/preflight/structure per template plus command wiring.
- **Complete Urdu UI (Phase 3 batch 3)**: the i18n dictionary (`src/ui/i18n/menuTranslation.ts`) now covers the full app chrome — 16 new keys for list/style/selection tools (`bulletLibrary`, `numberingLibrary`, `changeListLevel`, `lineSpacingOptions`, `modifyStyle`, `renameStyle`, `removeFromStyleGallery`, `addGalleryToQat`, `selectAll`, `selectAllMatching`, `selectObjects`, `standardJustify`, `straightLine`, `stopPlayback`, `nativeOsPassthrough`, `nativeOsKeyboardHelp`); all previously hardcoded English action labels in the ribbon, read-aloud toolbar and visual keyboard now resolve through the dictionary.
