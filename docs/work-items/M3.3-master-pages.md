# Work Item: M3.3 Master Pages & Running Header Elements

Status: Approved  
Milestone: M3 (Document Production Beta)  
Owner: Core Architecture Team  

## User outcome

Users can define Master Pages (`MasterPage` definitions with running headers, footers, and background elements), apply master pages to page ranges, override selected master objects per page, and automatically inherit master page updates across dependent pages.

## Problem and evidence

Publishing multi-page books and newspapers requires master page templates so headers, footers, page borders, and section headers update automatically across all pages.

## Scope

### Included

- **Master Page Domain Model (`types.ts`, `schema.ts`)**:
  - `MasterPage` interface with `objects` and `objectOrder`.
  - `masterPageId` and `masterOverrides` properties on `Page`.
  - `masterPages: Record<MasterPageId, MasterPage>` on `RePageDocument`.
- **Master Page Engine (`src/domain/layout/masterPageEngine.ts`)**:
  - `createMasterPage(name, width, height)`
  - `applyMasterToPages(doc, masterId, pageIds)`
  - `overrideMasterObject(doc, pageId, masterObjectId, overrides)`
  - `resolvePageCompositeObjects(doc, pageId)` merging master objects + local page objects.
- **Unit Tests (`src/domain/layout/masterPageEngine.test.ts`)**:
  - Verification of master page creation, range application, override merging, and composite resolution.

### Excluded

- Dynamic script running headers (deferred to M3.4 Page Numbering).

## Acceptance criteria

- [x] Master page definitions validate under Zod schema.
- [x] `applyMasterToPages` attaches master page pointers to target page ranges.
- [x] `resolvePageCompositeObjects` merges master objects and page-specific overrides cleanly.
