# Work Item: M2.2 Urdu Rich-Text Schema & Validation

Status: Approved  
Milestone: M2 (Urdu Typography Beta)  
Owner: Core Architecture Team  

## User outcome

Rich text inside Urdu stories is stored in a clean, structured ProseMirror/Tiptap compatible document format representing paragraphs, hard breaks, text direction, alignment, line heights, and marks (bold, italic, underline, font family, font size, color) without relying on arbitrary HTML string blobs.

## Problem and evidence

Storing text as unconstrained HTML introduces security vulnerabilities (XSS), inconsistent styling, and character corruption. RePage requires a canonical rich-text schema validated by Zod.

## Scope

### Included

- Canonical JSON nodes: `DocNode`, `ParagraphNode`, `HardBreakNode`, `TextNode`.
- Structured marks: `bold`, `italic`, `underline`, `fontFamily`, `fontSize`, `color`, `characterSpacing`.
- Text direction (`rtl`, `ltr`, `auto`) and alignment (`start`, `center`, `end`, `justify`, `right`, `left`).
- Zod validation schema for rich-text structure (`richTextDocumentSchema`).
- Plain text extraction (`extractPlainText`) and safe HTML conversion (`sanitizeHtmlToRichText`).
- Comprehensive unit tests in `src/domain/rich-text/richText.test.ts`.

### Excluded

- Direct DOM editing UI (handled in M2.3 Tiptap overlay).

## Acceptance criteria

- [x] Rich-text document format strictly validates through Zod.
- [x] Arbitrary HTML script injection or unvalidated tags are rejected/sanitized.
- [x] `extractPlainText()` accurately extracts text including multi-line paragraphs and hard breaks.
- [x] Urdu text marks (bold, italic, underline, font family, font size, color) round-trip cleanly.

## Verification

- Unit tests in `src/domain/rich-text/richText.test.ts`.
- `npm run check` pipeline execution.
