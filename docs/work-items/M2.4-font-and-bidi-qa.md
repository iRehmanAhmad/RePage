# Work Item: M2.4 Font and Bidi QA & Unicode Test Suite

Status: Approved  
Milestone: M2 (Urdu Typography Beta)  
Owner: Core Architecture Team  

## User outcome

Urdu documents containing mixed-direction content (English words, URLs, email addresses, phone numbers, dates, parentheses, Eastern/Western digits, RLM/LRM bidi marks, ZWNJ/ZWJ joiners, and honorifics) render, edit, save, and round-trip without character mutation or code-point loss.

## Problem and evidence

Mixed RTL/LTR content often suffers from reversed punctuation, corrupted URLs/phone numbers, or missing ligature joiners if bidi marks or code points are mutated during state serialization.

## Scope

### Included

- Expand `URDU_UNICODE_FIXTURES` in `src/domain/unicode/fixtures.ts` to cover:
  - Urdu paragraphs with English phrases.
  - Phone numbers and dates.
  - URLs and email addresses.
  - Parentheses, brackets, and quotes (`« »`, `( )`, `[ ]`).
  - Arabic and Persian character variants (`ک/ك`, `ی/ي`).
  - RLM (`U+200F`), LRM (`U+200E`), ZWNJ (`U+200C`), ZWJ (`U+200D`), FSI (`U+2067`), PDI (`U+2069`).
  - Honorifics (`ﷺ`, `رضی اللہ عنہ`).
- Integrity validation helper `validateBidiFixtureContent(text)` ensuring complete code-point preservation across JSON round-trips.
- Unit tests in `src/domain/unicode/fixtures.test.ts`.

### Excluded

- WebGL shader glyph rendering (deferred to export phase).

## Acceptance criteria

- [x] All 10 Bidi typography fixtures pass strict code-point preservation checks.
- [x] Round-trip JSON serialization preserves ZWNJ, ZWJ, RLM, LRM, and directional isolates exactly.
- [x] No replacement characters (`U+FFFD`) or unhandled BOMs are introduced.
