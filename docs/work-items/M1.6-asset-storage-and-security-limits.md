# Work Item: M1.6 Package Asset Storage, SHA-256 Hashing & Security Limits

Status: Approved  
Milestone: M1 (Local Page-Layout Alpha)  
Owner: Core Architecture Team  

## User outcome

Users can safely embed image assets (PNG, JPEG, WebP) into portable `.urdup` packages with verified SHA-256 hashes, deduplication, and protection against malicious ZIP bombs or memory overflow attacks.

## Problem and evidence

Currently, baseline `.urdup` package creation ([urdupPackage.ts](file:///c:/Users/TOSHIBA/Documents/Urdu%20Software/src/persistence/package/urdupPackage.ts)) serializes canonical document JSON but does not yet write or verify separate binary asset files, check SHA-256 asset hashes (F-003), or enforce hostile package expansion limits (F-004).

## Scope

### Included

- Asset binary storage inside `.urdup` packages under `assets/{sha256}.{ext}`.
- SHA-256 hash generation and verification upon package import/export.
- Deduplication of identical image assets by SHA-256 content hash.
- Enforcing security boundaries: maximum decoded pixel count (25 MP), max asset size (50 MB), max ZIP compression ratio (10x).
- Hostile ZIP inspection tests with corrupted hashes, missing assets, and unsafe paths.

### Excluded

- SVG vector sanitization parser (deferred to M1.6 phase 2).
- Server-side asset hosting or cloud syncing.

## Design

1. Extend `urdupPackage.ts` to inspect `document.assets` map.
2. Calculate SHA-256 hash using Web Crypto `crypto.subtle.digest('SHA-256', arrayBuffer)`.
3. Verify asset hashes on load. Throw clear validation errors on mismatched or missing binary assets.

## Compatibility impact

- **Document schema/migration**: No schema version change required; schema v1 already defines `AssetReference`.
- **Autosave/recovery**: Assets stored transactionally in IndexedDB.
- **Undo/redo**: Pure domain command updates.
- **Security/privacy**: Hardened against malicious ZIP entries, zip-bombs, and corrupt hashes.

## Acceptance criteria

- [x] Image asset binaries round-trip cleanly through `.urdup` package files.
- [x] Identical images share the same SHA-256 hash asset entry without duplication.
- [x] Hostile package inspection rejects mismatched hashes, missing assets, and unsafe relative paths.
