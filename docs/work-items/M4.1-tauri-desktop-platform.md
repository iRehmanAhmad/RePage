# Work Item: M4.1 Introduce Tauri 2 Desktop Shell & PlatformServices Architecture

Status: Approved  
Milestone: M4 (Cross-Platform Desktop Release Candidate)  
Owner: Core Architecture Team  

## User outcome

Desktop integration using a lightweight Tauri 2 shell (`src-tauri/`) with least-privilege capability permissions, while preserving 100% browser-compatibility for the domain and editor core via the `PlatformServices` abstraction layer.

## Problem and evidence

The application needs to run both as a web application in modern browsers and as a native desktop executable (Tauri 2) without coupling domain models or editor logic directly to desktop IPC APIs.

## Scope

### Included

- **Platform Abstraction Layer (`src/platform/platformServices.ts`)**:
  - Defined `PlatformServices` interface (`saveFile`, `openFile`, `getSystemFonts`, `platformType`).
- **Browser & Tauri Implementations (`browserPlatform.ts`, `tauriPlatform.ts`)**:
  - `browserPlatform.ts`: Browser DOM file dialogs and Blob downloads.
  - `tauriPlatform.ts`: Native desktop file dialogs with automatic browser fallback detection (`window.__TAURI__`).
- **Tauri 2 Configuration (`src-tauri/`)**:
  - `src-tauri/tauri.conf.json`: App config with least-privilege security capabilities.
  - `src-tauri/Cargo.toml`: Tauri 2 Rust manifest.
  - `src-tauri/src/lib.rs` & `main.rs`: Native desktop application entrypoints.
- **Unit Tests (`src/platform/platformServices.test.ts`)**:
  - Verification of platform service contracts and fallback mechanisms.

### Excluded

- Native C++ font system bindings (deferred to M4.3).

## Acceptance criteria

- [x] `PlatformServices` provides unified file save/open interface across browser and desktop.
- [x] Core domain and editor packages compile without Tauri runtime dependencies.
- [x] `src-tauri/` configuration validates under Tauri 2 schema.

## Verification

- Unit tests in `platformServices.test.ts`.
- `npm run check` pipeline execution.
